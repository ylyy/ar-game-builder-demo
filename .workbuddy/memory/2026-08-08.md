## VRM 加载后立刻强制 T-pose（"没开摄像头身体也扭曲"的根因）
- 用户反馈：刷新页面、状态栏"就绪"，但角色已经停在扭曲姿势（手在头后、身体侧倾）。
- 根因：**示例 VRM 文件（VRM1_Constraint_Twist_Sample）本身的导出姿势不是 T-pose**——它带非零骨骼旋转（"Twist" 模型本来就是为了展示 twist 约束而留了非零旋转）。代码加载 VRM 后没有清零骨骼 → 没开摄像头时，渲染的就是模型出厂的"扭曲姿势"，看起来像识别错位。
- 修法：`src/retarget.ts` 加 `applyRestPose()`（清零所有 SEGMENTS 骨骼 + hips 位置，**不清零追踪/不暂停**）。`src/main.ts` boot() 在 `new Retargeter(vrm)` 后调用一次，让初始就是干净 T-pose。已有 `reset()` 用于"重置姿态"按钮（带 paused）。
- 教训：不同来源的 VRM 导出姿势五花八门，加载后必须主动清零，不能假设文件是 T-pose；以后换模型也要走同样的"加载即清零"。

## 修复：头「消失/翻扣到身体后方」—— 头骨 rest 方向硬编码错误
- 用户截图：角色头部不在脖子正上方，反而在身体后方/腿部区域出现头发。
- 根因排查：解析 `public/models/VRM1_Constraint_Twist_Sample.vrm` 的 GLB JSON，发现该模型头骨的 rest 旋转非恒等——local +Y 指向世界 +Z（正前）、local +X 指向世界 +Y（正上）。也就是说这个模型的头骨 local +Y 不是"向上"，而是"脸朝前"。
- 代码问题：`applyRestPose()` 会把头骨 quaternion 清零为 identity，导致 local +Y 指向世界 +Y（脸朝天）；而 `retarget.ts` 硬编码 `restDir.set('head', (0,1,0))`，再用 `setFromUnitVectors((0,1,0), 躯干竖直向量)` 把头骨 local +Y 对齐到躯干向上。结果头骨被驱动成"脸朝天/顶朝后"，从正面看就是头扭到身体后方、头发垂到腿附近。
- 修复：`src/retarget.ts` 构造时捕获头骨原始 rest 旋转 `headRestQ`，计算 `headUpLocal = (0,1,0).applyQuaternion(headRestQ.invert())`——即"世界向上"在头骨 local 空间对应哪个轴。以此作为 head 的 restDir 参与 setFromUnitVectors，保证 applyRestPose 后头骨的"真正朝上"轴向能被正确对齐到躯干竖直方向。
- 验证：本地 build 通过，bundle 哈希更新；线上已验证引用新 `index-DkSj1deP.js`。
- 仍需要用户做的：截图里角色 Y 偏移 1.20，说明之前被手动拖高了，头可能还在视口外；按「重置位置」让角色回到脚底贴地，再观察头部。
- 教训：①不同 VRM 模型的骨骼 rest 朝向差异巨大，不能对头骨硬编码 (0,1,0)；②`applyRestPose()` 会改变所有骨骼的基准朝向，rest 方向必须与清零后的 identity 姿态匹配；③遇到"某块肢体方向错 180°/90°"先查 GLB 里该关节的 rest rotation，而不是凭直觉调符号。

## 诊断：对照 MetU 源码确认"映射失败"是算法问题（2026-08-10）
- 用户要求直接跑 GanniPiece/MetU（MediaPipe→Unity 骨架映射）。本机无 Unity Editor（只有 Unity Hub），MetU 需 Unity 2021.3.3f1 + 自编译 MediaPipe C++ 插件，无法直接运行。
- 改用 API 拉取 MetU 全部核心 C# 源码分析（/tmp/MetU 仅 sparse 拉到 Assets 部分，源码用 raw.githubusercontent.com 抓取）：
  - 坐标：`SpineCalculator`/`LeftLimbJointCalculator` 全部 `-X/-Y/-Z` 取反 → 与我们的约定互相印证。
  - 躯干：`SpineCalculator` 用 11/23 与 12/24 两点（左右肩髋连线）建轴；`HipCalculator` 用 23/24 髋连线。
  - 四肢：`LeftShoulderCalculator` 用 `FromToRotation(-obj.right, v_shoulder_elbow)` 方向对齐 + `Cross(v_shoulder_elbow, v_elbow_wrist)` 法线拧转（twist）。
- 结论：**是算法问题**。我们躯干四根骨全用单方向，转身/侧倾/扭转丢失；MetU 和 kiarina 都做躯干双轴。
- 修法：移植 kiarina 躯干 basis（左右髋×肩 4 点，hips 0.5/spine 0.25/chest 0.15/upperChest 0.1 权重 slerp）；四肢保持单方向（参考实现同样不解四肢 twist）。已部署 Pages。
