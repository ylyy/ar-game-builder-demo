## 修复：局域网/手机访问摄像头灰色（安全上下文问题）
- 现象：手机/其他设备通过 `http://192.168.x.x:5173` 打开，摄像头权限灰色不可用。
- 根因：getUserMedia 仅在安全上下文可用，明文局域网 IP(http) 不是安全上下文。
- 修法：装 `@vitejs/plugin-basic-ssl`(devDep)，`vite.config.ts` 加 `plugins:[basicSsl()]`，dev server 改走 HTTPS。手机访问 `https://192.168.3.10:5173` 并点「高级→继续访问(自签名证书)」即可授权摄像头。
- 同机测试直接用 `https://localhost:5173` 即可。

## 修复：`初始化失败：dbg is not a function`
- 现象：上一轮加调试读数后，用户浏览器报 `dbg is not a function`，但当前源码里没有任何 `dbg()` 调用（只有 `dbgX/dbgY/dbgZ` 元素引用与 `id="dbg"` div）。
- 排查过程：
  - grep src/index.html/node_modules：无 `dbg()` 调用（MediaPipe bundle 只有 wasm 内部 emscripten 的 dbg，非 JS 运行时调用）。
  - 发现**同时有两个 vite 在跑**（5173 + 5174）：之前 `pkill -f vite` 在沙箱里没杀干净旧进程，浏览器可能吃到旧 HTML + 新 JS 的不一致组合。
- 修复：
  - `id="dbg"` div 会生成全局 `window.dbg`，与任何把 dbg 当函数用的旧缓存/扩展代码相撞 → 全部改名：div→`#offset-panel`，`dbg-x/y/z`→`off-x/y/z`，变量同步改名，页面不再含 `dbg` 标识符。
  - 调试读数加空值保护（面板缺失也不再拖垮主循环）。
  - 按 PID 杀掉 5173/5174 两个旧服务，`npm run dev -- --force` 重启单个干净服务（清 vite 缓存），并提示用户硬刷新（Cmd+Shift+R）。
- 教训：①HTML id 会生成全局变量，调试用 id 别起 `dbg`/`debug` 这类易撞名；②沙箱内 pkill 可能杀不干净，换端口/重启前先 `lsof -iTCP -sTCP:LISTEN` 确认；③浏览器异常报错先怀疑「旧页面+新模块」混载，强制刷新是最快验证手段。

## 修复：角色上下颠倒（头在下、脚在上）
- 现象：截图显示 VRM 角色整体 180° 上下颠倒，头朝下、脚朝上，正脸仍朝相机。
- 根因（retarget.ts toVec）：MediaPipe Pose **worldLandmarks 是世界坐标（米制、原点在髋中心），Y 轴向上**；但代码按"图像坐标 Y 向下"的假设对 y 取了反（`-p.y`），导致整个人垂直镜像颠倒。Z 取反（world z+ 远离相机→朝相机=VRM 正前方）是对的，保留。
- 修复：
  - `toVec` 改为 `(x, y, -p.z)`：y 不再取反；保留 x 不取反（person's right=VRM +X）与镜像按钮兜底。
  - 追加 `flipY` 调试开关（UI「翻转Y」按钮）兜底设备/模型约定差异，切换时清空平滑缓存。
  - 顺带修正 restDir 静止方向的计算帧：原代码用「骨骼自身」世界四元数转本地，应为「父骨骼」世界四元数（与 update() 的 parent.getWorldQuaternion 一致），否则 T-pose 下带自身旋转的手臂等骨骼 rest 方向算错、肢体姿态会歪。
- 坐标约定最终版：x 不取反、y 不取反、z 取反。
- 官方参考：MediaPipe Pose 官方 demo https://google-ai-edge.github.io/mediapipe-samples-web/#/vision/pose_landmarker ；同类完整实现参考 kiarina/labs mediapipe-holistic-vrm（方向对齐法，与本项目一致）。

## 修复：测试视频导致身体扭曲 + 重置不持久
- **根因**：用户提供的"测试视频"实际是豆包AI 生成的 2D 卡通动画。MediaPipe Pose Landmarker 是真人人体检测模型，对 2D 卡通会输出"幻觉"关键点 → VRM 被驱动成扭曲姿态。被误以为是"bug"，实际是视频素材不适配。
- **修复**：
  - **`src/retarget.ts`**：① 加 `minVisibility=0.5` 关键点置信度过滤——某段骨骼所用关键点 visibility 平均低于阈值就跳过（保持上一帧姿态），避免部分入镜/识别失败时把身体掰歪。② 加 `paused` 标志 + `pause()`/`resume()`/`isPaused()` —— reset() 改为"清零到 T-pose + 暂停追踪"，resume 时清空平滑；update() 在 paused 时直接 return false。③ 配套冻结 1.2s 的旧文案自动恢复移除（reset 现在持续暂停，由按钮显式恢复）。
  - **`src/main.ts`**：① 移除 `loadVideoFile('/test-video.mp4', ...)` 自动加载（卡通视频是元凶）。② 「重置姿态」改为 `retargeter.reset()` + 启用「继续追踪」按钮 + 状态文案「已重置为 T-pose（追踪暂停中...）」。③ 新增「继续追踪」按钮 wire `retargeter.resume()`。④ 加载视频文件时自动 resume（避免新视频进来还被 paused 卡住）。
  - **`index.html`**：① 加 `btn-resume` 按钮（默认 disabled）。② 顶部提示改为「MediaPipe Pose 只能识别真人，测试动画/卡通画面会扭曲」。③ 「重置姿态」和「继续追踪」并排。
  - **删除 `public/test-video.mp4`**（用户的原文件仍在 Downloads 保留），避免在文件选择器里再误选。
- 教训：① MediaPipe Pose 仅适配真人；接视频源时先验证材质。② "重置" UX 应让用户能持续停在 T-pose，不要几秒后自动 snap back。③ 关键点 visibility 是 MediaPipe 提供的质量信号，**必须用**——以前完全忽略，遇到低置信度关键点就会把肢体驱动到垃圾位置。
